# Doctor D's BBQ — Inventory & Sales System

A database-driven inventory and sales system for a small BBQ-sauce business that sells through Shopify,
wholesale accounts, farmers markets and direct sales. The owner enters each sale once; the database
works out sales tax, card fees, the licensing scholarship, product cost, profit and stock, and every
report updates instantly.

*ISE 519 Graduate Project — Data Systems Prototype & Demo.*

## What it does

- **Sales** — record one order, or a whole farmers-market day as two totals (cash and card). Revenue is
  split between products by jar count, so bundle deals are shared fairly.
- **Automatic money math** — county sales tax (NC 2% qualifying-food rate on items + shipping), Shopify
  fee (2.9% × order total + $0.30), 16% scholarship on co-branded sales, product cost and gross profit.
- **Inventory** — production batches, breakage / samples / giveaways, shelf counts with one-click
  reconciliation. Stock is calculated, never typed, and overselling is blocked by the database.
- **Reports** — monthly profit, sales tax by county, the monthly scholarship report, sales trends by
  month or year, and reorder suggestions. Every table downloads as CSV.
- **Tax rates** — rates for 1,796 US counties, with a one-click refresh of the home state's rates.
- **Settings** — prices, costs, fees, tax rate, products, channels and business rules are edited on
  screen. Nothing is hard-coded.

## Run it locally

**You need:** PostgreSQL (any recent version), Python 3.10+, and a SQL client such as DBeaver or `psql`.

1. **Create the database.** Open `DoctorDs_Inventory_System.sql` in DBeaver, connect to the `postgres`
   database, and run the whole script (DBeaver: **Alt+X**). Or from a terminal:
   ```
   psql -U postgres -d postgres -f DoctorDs_Inventory_System.sql
   ```
   The script drops and recreates its own tables, so it can be re-run at any time to reset the data.

2. **Install the Python package.**
   ```
   cd dashboard
   python -m venv .venv
   .venv\Scripts\activate          # macOS / Linux: source .venv/bin/activate
   pip install -r ../requirements.txt
   ```

3. **Add your database password.** Copy `local_settings.example.json` to `local_settings.json` and put
   your PostgreSQL password in it. That file is in `.gitignore`, so it is never committed.
   (Alternatively, set the environment variable `DD_DB_PASSWORD`.)

4. **Start the dashboard.**
   ```
   python app.py
   ```
   It opens <http://localhost:8000> in your browser.

The connection defaults to `localhost:5432`, user `postgres`, database `postgres`. To use another
database, set `DD_DB_NAME`; to change the host or user, edit the `DB` block at the top of `app.py`.

## How it works

1. **Capture** — the owner enters only what they know: what sold, for how much, and where.
2. **Calculate** — one database function (`fn_finalize_sale`) computes tax, fees, scholarship, cost and
   profit for every sale, whether it comes from the app or the sample data. On-hand stock is a view
   (produced + adjustments − sold), and a trigger refuses any sale larger than the stock.
3. **Report** — views such as `v_monthly_report`, `v_scholarship_owed` and `v_inventory_on_hand` feed
   the dashboard and the CSV downloads, so the numbers are identical in the app and in SQL.

## Sample data

The 17,471 records (5,000 sales, 10,000 sale lines, 501 customers, 100 production batches, 1,846 tax
rows and the settings) are generated by the SQL script, with sale dates covering the ~21 months up to
the day it is run. They are realistic but synthetic — not real business records.
